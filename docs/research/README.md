# デザイン刷新リサーチ サマリー

インサイダーゲームツール（LINE BOT紹介・遊び方マニュアルサイト）のデザイン全面刷新に向けた事前リサーチのまとめ。ゴールは「見た人をすごく感動させる、最新トレンド感とかわいさ」の両立。

調査は6領域に分けてサブエージェントが並列で実施した。各詳細は以下を参照。

- [01-benchmarks.md](01-benchmarks.md) — 類似ゲーム/LPサイトのベンチマーク分析
- [02-trends.md](02-trends.md) — 2025-2026年のデザイントレンド
- [03-visual-language.md](03-visual-language.md) — 配色・タイポグラフィ・イラスト方針
- [04-motion.md](04-motion.md) — モーション・インタラクション
- [05-ux-flow.md](05-ux-flow.md) — UX・導線・ページ構成
- [06-constraints.md](06-constraints.md) — 現行サイトの技術的制約棚卸し

## 結論：デザインコンセプト（案）

**「かわいい秘密結社」** — 明るくかわいい表の顔と、正体隠匿ゲームらしい謎めいた裏の顔を、場所を分けて使い分けるコンセプト。全面カラフル・全面ダークのどちらにも振り切らず、メリハリで「安っぽさ」を回避する。

- ベースは明るいパステル系（親しみやすさ・かわいさを第一印象に）
- 役職紹介・ルール説明などゲーム性を伝えたい箇所に限定してダーク×ネオンを差し込む
- マスコットキャラクターが「市民・インサイダー・マスター」等の役職を体現し、ルール説明のナビゲーター役になる
- 全体を通じて「弾む・にじむ・ふわっと浮く」柔らかいモーション言語で統一する

## 領域別の主要な結論

### ベンチマーク（[詳細](01-benchmarks.md)）
15サイト（Oink Games、犯人は踊る、ito、Codenames、Among Us、Jackbox Games、人狼ジャッジメント、闇鍋人狼、LINE公式LP事例、Awwwards掲載サイト等）を調査。共通パターンは以下の4点。

1. **主役を信じて背景を引き算する** — Oink Games、IZANAMI、sakazukiに共通。装飾を削り、キャラクターやコピー1行を際立たせる。
2. **対立ではなく体験のメタファーで和らげる** — ito（会話）、闇鍋人狼（鍋）は「疑い合う怖さ」を優しいモチーフで包んでいる。
3. **体験を先に疑似体験させる** — 実際のトーク画面（吹き出しUI）モックをファーストビュー直下に置くと効果的。
4. **ブランドボイスで個性を作る** — CTA文言やコピーに世界観を込め、無機質な業務文言を避ける。

### トレンド（[詳細](02-trends.md)）
2025-2026年の一次情報を調査。**採用推奨**：マスコットキャラクター＋Digi-Cuteスタイル（最優先）、バウンス/スクワッシュ&ストレッチのマイクロインタラクション、インタラクティブBento Grid、手描き風イラスト＋グレインテクスチャ、パステル＋ビタミンカラー、ヒーロー限定のスクロール連動タイポグラフィ。**見送り**：フル3D/重いWebGL、ダークモード全面採用、ニューモーフィズム全面適用、AI生成ビジュアルのそのまま使用、過剰なパララックス・汎用ストックフォト・文字の壁レイアウト。

### 配色・タイポグラフィ・イラスト（[詳細](03-visual-language.md)）
5配色パターンを提案（HEX付き）。推奨は**パターンA「パステル・ミステリー」**（ラベンダー`#F3EEF6`＋ペタルピンク`#F7C9DE`をベースに、ディープバイオレット`#5E3A87`とミッドナイトインク`#2B2438`で締める）を基調とし、緊張感を出したい箇所に**パターンC「ダーク×ネオン」**（`#17131F`＋ネオンマゼンタ`#FF3EA5`）を部分投入するハイブリッド運用。フォントは見出しに**Zen Maru Gothic**または**LINE Seed JP**、本文に**M PLUS Rounded 1c**（いずれもGoogle Fonts・OFLライセンスで商用無料）。イラストは簡略化した1〜2種のマスコット＋幾何学パターンのハイブリッドが、開発原則の「シンプルな実装」とも整合する。

### モーション・インタラクション（[詳細](04-motion.md)）
推奨は**「CSS/ネイティブAPIをベースにし、ヒーローとCTAの見せ場にのみGSAP（core + ScrollTrigger、必要ならSplitText）をピンポイント投入するハイブリッド構成」**。2025年4月にGSAPの全プラグインが商用含め無料化されたためコスト障壁がない。軽微なフェードイン等はIntersection Observer + CSSで賄い、バンドルサイズと保守コストを抑える。`prefers-reduced-motion`対応とモバイル配慮（`transform`/`opacity`限定、ホバー前提の演出を避ける）を設計の前提条件にする。

### UX・導線・ページ構成（[詳細](05-ux-flow.md)）
最重要の改善案は**「友だち追加」導線の一本化**。現状複数ページに分散しているCTAを1点に集約し、下スクロールで隠れ上スクロールで再表示する高さ44〜50px以内のフローティングCTAを全ページ共通で設置する。その他: トップページをヒーロー→魅力訴求→使い方（3ステップ）→CTAの順に再構成、`rule.html`をステップ形式＋簡易イラストへ、ナビゲーションはハンバーガーではなくボトム固定の3項目（ルール／友だち追加／よくある質問）、`opinion.html`はカテゴリ分け＋アコーディオン形式に整理。

### 技術的制約（[詳細](06-constraints.md)）
最重要の注意点は**`google-site-verification`メタタグが`index.html`にしか存在しない**こと（Search Console所有権確認用、刷新時に消さないよう明示チェックが必要）。その他、慎重な移行が必要なもの：`public/_redirects`（`/webcontent/*`互換リダイレクト）、ページごとに異なるOGP画像・説明文、favicon、`netlify.toml`のビルド設定、`src/config.ts`のAPI_BASEと`line.html`の`userId`Cookie（バックエンド契約）。一方、CSS資産（`style.css`等、計約3037行、構造化されておらず命名衝突あり）や既存のヒーローアニメーション実装、`header.hbs`のサイドナビ（ページ間で不統一）は作り直し前提でよい。DOM操作（`pages/*.ts`）はCSSセレクタに強く依存しているため、HTML構造を変える場合は書き換えが必須。ロジック本体（`form-logic.ts`, `chat/logic.ts`）はHTML非依存で再利用可能。
