# リファクタリング提案

この文書は Phase 8 の提案をまとめたものです。今回のリファクタリングでは、既存ページの表示と外部 API 契約を優先し、以下は実装していません。

## D18: CSS ファイル名の整理

`line.css` はチャット UI、`lineStyle.css` は記事内の会話風表示を担当しており、用途が異なります。セレクタの衝突は確認されていないため、直ちに統合・改名しません。

次回の CSS バンドル化のタイミングで、`line.css` を `chat.css`、`lineStyle.css` を `article-conversation.css` に改名し、HTML とビルド設定を一括更新する案を提案します。改名時には生成後の CSS URL を確認し、既存の HTML から直接参照される公開パスを不用意に変更しないようにします。

## D19: 未参照の可能性がある画像

画像は HTML/CSS/JSON からの参照だけでなく、外部 API のレスポンスや外部 URL から参照される可能性があります。したがって、grep で未参照に見える画像も今回は削除しません。

将来は次の棚卸しを行います。

1. HTML、CSS、JSON、TypeScript、API レスポンス例から参照を収集する。
2. 本番の Network ログまたはアクセスログで実使用を確認する。
3. 必須・確認待ち・削除候補に分類し、削除候補は一定期間の監視後に別変更として削除する。

## CSS のバンドル化

現在の既存 CSS は `public/contents/css/` に置き、従来どおりの URL で配信しています。Vite の CSS エントリへ移行する場合は、ページ単位のエントリを作り、画像・フォント URL の解決結果と本番のキャッシュキーを確認します。複数ページで共有する CSS は共通チャンクにまとめますが、全ページへ Tailwind の preflight を適用しない方針は維持します。

## 既存カスタム CSS の段階的な Tailwind 移行

`style.css` などの大規模な既存 CSS は一括変換せず、変更が発生したコンポーネントから段階的に移行します。まず色・余白・ブレークポイントをデザイントークンとして整理し、ページ単位でスクリーンショット比較を行います。既存クラスの削除は参照調査と視覚確認が完了した単位に限定します。

## 記事ページのテンプレート化

今回の共通化はヘッダー、ロゴ、メニュー、フッターのパーシャルに留めています。記事本文のリライトは行いません。

将来は記事ごとのタイトル、OGP、公開日、本文アセットをデータとして管理し、同じレイアウトを MPA のビルド時に生成する構成を検討します。既存 URL と個別メタデータを固定したまま、まず 1 ページで試行してから全記事へ広げます。

## ESLint / Prettier

TypeScript の未使用 import、危険な DOM 操作、Promise の扱いを ESLint で検出し、Prettier で HTML・TypeScript・設定ファイルの整形を統一する案です。導入時には既存ファイル全体を機械的に整形せず、`src/` と設定ファイルから適用範囲を始めます。

## GitHub Actions CI

Node.js の LTS 版を固定した GitHub Actions で `npm ci`、`npm run build`、`npm run test` を pull request ごとに実行します。Netlify の本番デプロイは既存の master push 運用を尊重し、CI ではデプロイを重複させません。

## particles.js の CDN 依存

`line.html` の背景パーティクルは挙動維持を優先して CDN 参照を残しています。将来ローカル配信または別実装へ移行する場合は、背景描画のスクリーンショット比較と CDN 障害時の表示を確認してから判断します。
